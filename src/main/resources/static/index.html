Inventory Cloud Service

A backend for managing stock and customer reservations. Database transactions protect inventory when requests arrive at the same time.

Try a local request

Start the local Docker environment using the README. Use the administrator password from your local .env file. Curl will prompt for it.

curl --user admin -H 'Content-Type: application/json' \
  -d '{"sku":"WIDGET-01","name":"Widget","initialQuantity":10}' \
  http://localhost:8080/api/v1/products

Behavior you can rely on

Reservations decrement available stock in the same transaction that creates the reservation. Cancelling restores stock once, including when the request is repeated. Customers can only read or cancel their own reservations.

Send a unique Idempotency-Key header when creating a reservation. Retrying with the same key, product, and quantity returns the original reservation without consuming stock again. Use a new key for each intended reservation; changing the request under an existing key returns a conflict.

Production uses signed bearer tokens with issuer and audience validation. Password-based demo accounts are enabled only in the explicit local and test profiles.

Errors and operations

Errors use application/problem+json. Every response carries an X-Request-ID for log correlation. List endpoints accept page and size; page numbering starts at zero and size is limited to 100.

API v1 · Health links report the running service; this guide does not imply a cloud deployment.
